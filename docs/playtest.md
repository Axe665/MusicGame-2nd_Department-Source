# 试玩与判定

按 F5 从播放头开始试玩，Shift+F5 从头开始。试玩用的是真实的判定、音效和结算，和编辑器共用同一套边界求值、最近点和校验逻辑。

## 开局

- 先显示环自绘的加载和 READY 层，然后按当前 BPM 倒数一小节：4/4 拍就是 4 拍，滴答声落在拍上，最后一拍就是第一颗音符。按 Esc 取消并回到编辑器。
- 时间轴自动回退「1 秒 ÷ 音符速度 + 0.5 秒」，保证 GO 之后第一颗音符仍有完整的飞入时间。回退区间里更早的音符不计分。
- 时间轴允许退到负拍（预读时间 + 0.5 秒）。osu! 谱的第一颗音符通常在音频的 2–5 秒处，现在会直接利用音频自带的前奏，GO 之后不会贴脸。如果第一颗音符就贴着音频的第 0 秒，GO 之后最多等 1.5 秒（无声）让音符飞入，音频延后起播。
- 导入的负拍前奏：最早的音符会自动平移到第 0 拍，同时调整 offset，从头试玩不会漏掉前奏。

## 速度

- **音符速度**：在运输条和试玩设置里调，倍率 0.05×–3.0×，步进 0.01。音符从出现到该打的时间 = `1 秒 ÷ 倍率`，**与 BPM 无关**：BPM 只表示谱面密度，不应该让高 BPM 的曲子更难读。音符速度只改飞行时长，不改判定窗口。它是编辑器和试玩的会话选项，不写入谱面。
- 飞行时长的基准固定为 1 秒（`Chart.NOTE_FALL_MS`），谱面不再保存 `pre_read_ms`。
- **倍速**：在试玩设置里（F5，或暂停菜单 →「试玩设置」）调，范围 0.5×–2.0×，步进 0.05。
  - **只对试玩生效**，编辑器试听始终是 1×。
  - **声音不变调**：用 ffmpeg 的 `atempo` 预先生成该倍速的音频并缓存。每个新倍速第一次大约要等 2–5 秒，之后立即可用。
  - BGA 视频跟随倍速；READY 倒计时仍然是真实的 2 秒。
  - 没有 ffmpeg 时回退为变调播放，并在日志和提示里说明。
  - 在局中修改，要在重开本局后才生效。倍速设置只对本次运行有效。

## 判定窗口

| 对象 | PERFECT | GREAT | GOOD | BAD | MISS |
|---|---|---|---|---|---|
| Tap / Hold 头 / Path 头 / Anchor | ±50 ms | ±100 ms | ±150 ms | ±200 ms | 超过 200 ms |
| Path 尾 | ±120 ms | ±180 ms | ±300 ms | — | 晚于 300 ms |
| Seek | 只有 PERFECT 和 MISS 两档 | | | | |
| Bell | 在场即 PERFECT | | | | 没贴住 |

- BAD 不断连，也不计为命中。GREAT 和 GOOD 不断连。
- 只要按键，就能打 Tap、Hold 和 Anchor，不限定键位。
- **提前接收**：音符离判定环还剩 25% 半径（即预读时间的 25%）时开始接收按键。提前按下按 GOOD 结算，不会直接丢掉。
- Path 的头尾在窗口内都能命中，不会在窗口一开始就判 Miss。
- 判定状态还有 FULL / FRAY / LOST 和 COMBO。

## 输入

### 位置判定

- Tap、Hold 头、Path 头和 Anchor 按**按下那一刻鼠标的实际位置**判定，不只看角度条带。
- 先看鼠标离**画出来的条带**有多近，容差为 `POSITION_TOLERANCE_PX = 120`；Hold 头额外放宽 40px。
- 不够近时再看角度：鼠标落在音符角度 **±12°** 以内（`AIM_ANGLE_TOLERANCE_DEG`）也算命中。这样在环形谱上斜着挪鼠标，不会因为差几十像素就丢分；但角度差太多，或光标不在环上，仍然不算。
- 间隔不超过 0.25 拍的密集流改用扇区判定。

### 按键归属（防蹭键）

- 光标已经压在某颗音符的图形上（离中线 20px 以内）时，这颗音符优先拿到按键，不会被时间更近的邻键抢走。
- 漏掉前一颗之后，晚于音符时间的匹配额外加 10ms 代价，所以下一次按键优先给后面那颗。
- 刚命中一颗后的 50ms 内，额外的按键不能提前吃掉下一颗，避免手指蹭键把下一颗判成 GREAT。

### 鼠标按键

鼠标左键和右键默认和键盘一样，各算一个独立键位。试玩设置和暂停菜单里都有「鼠标左右键算 Tap」开关；关掉后左右键不参与判定，鼠标移动和滚轮 Seek 照常工作。这个设置写入 `settings.json`。

### 时钟

- 以音频为主时钟，做输出延迟补偿，并防止时间单调回跳。
- 按键事件按时间戳判定，减少一帧的输入延迟。
- 视频只是背景层，音频是唯一的判定时钟。起播和同步的细节见 [已知限制](limitations.md#试玩时钟)。

## 各类音符的判定

### Hold

Hold 绑定起手的那个键。在最后 1/2 拍内松手算 PERFECT；更早松手时按已按住的比例降级，不断连。

### Path

- **关闭轨迹**（检查器里的「显示轨迹」）：只判星头，等同 Tap；没有尾环、尾判和中段判定。
- **装饰 Path**（音符状态 False）：轨迹完整显示、星星照常沿轨迹走，但不参与判定，滑动也不会擦除轨迹。

**有序判定组**

- 轨迹按弧长（约 0.85R）、明显拐点和自交位置切成若干**有序判定组**。
- 走廊半径通常为 0.25R（常见视口下约 67px），短轨迹会缩小到轨迹长度的 18%；主要拐角放宽到 0.34R。
- 光标按顺序经过一组就消掉一组，允许向前跳过 1 组（跳区）；但总共不超过 3 组的短滑条禁止跳组。
- 星头命中后自动免除第一组（A 区免判）。
- 中段不需要一直按着键，头和尾分别计分。
- 判定组在环的局部坐标系里生成，所以环变形、旋转、倾斜、缩放以及任意平面滑条都适用。遇到自交或折返时，按前进方向过滤，避免走到另一支上。

**尾判**

- 身体的判定组清完后，**进入尾区就结算**。
- 参考点是**星星进入尾区的时刻**，不是滑条的终点。早到窗口按「尾区停留时间 / 4」扩展，上限 22 帧；晚到仍按终点计算。
- 早到不会掉 Miss，晚于 350ms 才 Miss。结束时只剩最后 1 组没消的，给 GOOD；差得更多才 MISS。
- 身体达标不会立刻触发尾判。提前进入尾区并停留，可以等到 PERFECT 的时间窗；提前离开则按真实接触的时间评分。
- 头部 MISS 之后，仍然可以从轨迹起点完成滑动，拿到尾判。

**反馈**

- 引导球继续按音乐时间移动，箭头按玩家已经走过的轨迹进度消除。
- 漏掉的段不计入实际覆盖，反复擦同一段也不会增加覆盖率。
- 同一次移动可以同时满足多条真实重叠的轨迹，但主要转弯、绕行方向和回环顺序仍然必须满足。

**容错**

- 头部命中时确认起始区域。
- 短暂离轨后，允许在前方有限范围内重新接上：180ms 内最多约 0.45R 或总长的 15%；离轨较久时收紧到 0.30R 或总长的 10%，两者取较小值。重新接上不会填满漏掉的段，也不能越过尚未到达的主要区域。
- 等待段提前 120ms 开始接收身体输入，但不早于头部的拍点。评分偏移不改变身体相对画面的启用时间。
- 暂停、重开、窗口失焦和切换 AUTO 都会切断移动记录。

### Bell

- 在判定线前后 ±110ms 内，光标贴住金键**当前可见的位置**（离键 55px 以内）就算「在场」。到达判定环之前、从圆心飞入的那一段也算。
- 同一串扫键 Bell（相邻间隔不超过 45ms、角度在变化）共享整串的提前窗口，一次扫过去时，后面的铃也能提前锁定，到各自的判定线再结算。
- 串里的 Bell 空间容差放宽到 75px，并画出同半径的淡金色光圈（看到多大就能打多大）；串外的 Bell 仍是 55px。
- 判定用**这一帧光标扫过的线段**求交，不要求停留，所以快速扫过一串 Bell 也不会因为采样点整帧跳过而漏判。
- 在场时收拢一圈金环表示锁定，到判定线才结算为 PERFECT。不用点击，不吸附，也不会提前消失。
- 没贴住判 MISS 并断连，计入连击和准确率，但不写入 BIA 和动态 offset，因为在场判定没有「按早」或「按晚」的含义。
- 命中特效复用 Tap 的 burst，颜色为金色。

### Seek

滚轮上滑为朝里，下滑为朝外。只有 PERFECT 和 MISS 两档。

Seek 长出前一小节起，环上会先亮起判定弧预告，并像呼吸一样一亮一暗：两拍一个周期，明暗频率是当前 BPM 的一半，最暗时仍留一层淡影。长出后交给音符本体，判定前 300ms 再转成就位高亮。

### Limit 红区

光标停在红区带上**累计满 200ms 直接判 MISS 并断连**。离开红区后计时清零；每局每个红区只断一次。红区带本身是环面上 0.68R–1.0R 的部分，环心的空洞不算。

### Trace

离开轨迹超过 250ms 会重置累计距离，判为 FRAY。

## 偏移与校准

- **判定偏移**：在试玩设置里手动填写，范围 −200…200ms；游戏内用 `[` / `]` 微调。数值写入设置。
- **「校准判定偏移…」**只写这一个值，两种方式二选一：
  1. 跟着 120 BPM 点击轨的**声音**点 8 次
  2. 看同步脉冲点 8 次

  两种都做、连着做，会把「跟声音的拍点误差」和「显示/反应延迟」重复计算两遍，结果反而整体偏早。
- **输出延迟**：只有驱动报告的值明显不准时才需要手填。0 表示使用驱动报告的值，大于 0 表示强制覆盖。校准只改判定偏移，不改输出延迟。
- **动态 offset**：勾选后，从第 8 次命中开始，每次命中按偏差的 5% 自动校准，自动部分最多 ±50ms。
- **把本局偏差写进本谱面**：结算页的这个按钮，会把本局的平均判定偏差反向加到**当前这张谱面**的 offset 上并存盘（按得早，offset 就变大）。只影响这一张谱面，导入谱面的时机偏差可以一首一首修。

## AUTO 自动演示

在试玩设置里勾选「AUTO 自动演示」，或在游戏内按 F8 切换；启动时加 `--auto` 也可以。

AUTO 把「完美演奏」合成为真实输入：Tap、Hold 头、Path 头和 Trace 头在判定时间按下按键，Hold 一直按到尾巴；合成的光标贴着 Path 和 Trace 走，去接 Bell，并避开红区。判定、特效、音效、连击和结算都是真实的，所以可以直接挂着看谱面。

结算页会标注 AUTO。AUTO 局不写最高分，也不参与动态 offset 校准。

## HUD

- **布局**：信息贴在环的左右两侧，垂直居中。
  - 左列：曲名和难度，可选显示进度百分比和用时，右对齐贴着环。
  - 右列：准度大字（两位小数）、评级章和连击。连击数从 2 开始显示，命中时轻微放大，断连时闪红 0.45 秒。
  - 环外有一条 8px 的进度带和 2px 的准度线，起点在 12 点钟方向。
- 五档判定计数只在暂停页的「本局状态」和结算页里显示。
- 连击单独画在音符层下面，下落的 Tap、Hold 和 Path 会盖住它；左右两列仍在最上层。
- **判定字位置**有五档：跟随音符、环内、环外（默认）、屏幕中心、关闭。偏移随 HUD 缩放和环半径变化，Tap、Hold、Path 和 Bell 的规则统一。
- 全部元素按窗口高度缩放，1024 到 2560 宽使用同一套布局，长曲名自动截断。
- 在「设置 → 界面」里可以调：
  - HUD 缩放：80 / 100 / 120%，默认 100%
  - 连击位置：屏幕中心 / 右侧 / 关闭
  - 进度仪表
  - 判定字位置
  - 判定字显示：全部 / PERFECT 以下 / GREAT 以下 / GOOD 以下 / 仅 MISS。「PERFECT 以下」就是隐藏 PERFECT
  - 透明度：100 / 85 / 70%
  - 左列四项的开关
- **偏差显示**：暂停页的「本局状态」里显示当前 OFF 和本局平均偏差；结算页「把平均偏差写成谱面 offset」会把两者一起用上。
- **命中特效**：命中后音符从落环时的尺寸整体放大到 1.5× 并淡出（osu!std 式的击打光），伴随扩散环、火花和环弧闪光，并显示 PERFECT / GREAT / GOOD / MISS 判定字。试玩中还会显示音符的类型标签。

## 暂停

- Esc 或暂停菜单会同时停住音频和 BGA 画面，恢复时音画重新对齐。
- 暂停菜单里可以调整 Path 启动指示、「显示 Path 判定区域」、鼠标按键开关等，也可以打开试玩设置。

## 结算

- 结算页给出判定偏差直方图、判定散布图（横轴是整首曲子的时间，纵轴 ±180ms，上方为 Late、下方为 Early，按判定等级着色）、平均判定偏差、不稳定率（UR）和命中统计。
- 目前提供分档判定、事件日志和调试用的准确率与评级，尚未采用正式的评分公式。
- 回放视频导出见 [故事板与回放导出](storyboard-and-replay.md#回放视频导出)。

## 画质与性能

### 画质设置

在「设置 → 画质」里设置，共 18 项，都只影响渲染、不影响判定，全部写入 `settings.json`：

| 选项 | 可选值 |
|---|---|
| 预设 | 极高 4× / 高 2× / 中 / 低 / 自动（按实测帧时间）；改动单项后显示「自定义」 |
| 帧率上限 | 60 / 120 / 144 / 240 / 垂直同步 / 不限，默认 120 |
| 2D 抗锯齿 | 关 / 2× / 4× / 8×；关闭可省 1.5–2.5ms |
| 3D 抗锯齿 | 关 / 2× / 4× / 8× / FXAA / TAA / 2×+FXAA / 4×+FXAA |
| 3D 环 | 开 / 关；关掉后走 2D 回退环 |
| 音符精细度 | 全画质 / 省电；省电模式把弧带采样从 1/4° 降到 1/6° |
| 音符光晕 | 开 / 关 |
| PERFECT 特效 | 开 / 关；关闭后 PERFECT 命中只留判定字，不出爆点、环外光扇和碎屑 |
| Path 画法 | 履带（粗，默认）/ 丝带（半透明） |
| 光标拖尾 | 长 / 短 / 关 |
| 命中特效 | 完整 / 精简 / 关；关闭后仍保留判定字 |
| 3D 环分辨率 | 高 0.85 / 中 0.65 / 低 0.5 |
| 小节线 | 开 / 关 |
| 背景明暗 | 关 / 25 / 50 / 75 / 100（默认），见 [故事板与回放导出](storyboard-and-replay.md#背景明暗) |
| 故事板 | 开 / 关 |
| 故事板背景层 | 开 / 关 |
| 视频导出编码器 | 自动（优先硬件）/ NVENC / QSV / VideoToolbox / VAAPI / libx264 |
| 渲染后端（重启生效） | 自动 / Vulkan / OpenGL 兼容 |

帧率上限默认 120；选 60 / 120 / 144 / 240 时会关闭垂直同步（否则在 60Hz 屏上不生效），选「垂直同步」才是跟随显示器刷新率。

### 弱机保护

连续两个 2 秒窗口的中位帧时都超过目标帧的 1.12 倍时，自动降一档：3D 环渲染分辨率在当前档位上再减 0.15（高 0.85 → 0.70、中 0.65 → 0.50、低 0.5 → 0.40）。目标帧取设置的上限和屏幕刷新率中更严格的那个。只降不升，避免来回抖动。

## Path 调试工具

- **输入诊断日志**：默认随试玩开启，按 `F9` 关闭或重新开启。日志写在 Godot 用户数据目录的 `logs/path_input_*.jsonl`（Windows 默认是 `%APPDATA%\Godot\app_userdata\Tamaki₃ 制谱器\logs`）。
  - 记录内容：谱面、判定偏移、判定组几何、当前光标和下一组、距离/容差/剩余组、输入批次以及完成状态。
  - 活动的 Path 每 200ms 采样一次，日志约 4 MiB 后停止记录。
  - 退出、重试或正常结束时关闭日志。遇到问题时可以先退出试玩，再拿最新的日志去分析。
- **显示 Path 判定区域**：按 `F10` 或在暂停菜单里开启，默认关闭。显示层读取的是实际判定模型：
  - 绿色：已消组
  - 蓝色：未消组
  - 橙圈：下一组
  - 红圈：MISS 后未通过的区域
  - 白圈：尾区

  文字显示当前组数、容差和剩余组数。
- **试玩事件日志**：记录试玩中的判定事件。
